## THE DECODED PINE STATE MACHINE (long, default flags — `vwema_bb_meanrev.py` already gets the *bands* faithfully via `_base.vwema_bb(period=20, alpha=0.9, std_mult=2.0, source="hl2")`; `upper = DSTUPPER`, `middle = DSTEVMA`, `lower = DSTLOWER`)

Pine tracks "which tier" via `strategy.closedtrades.exit_id(...)`: a `strategy.exit("1",...)` marks the trade as having reached tier 1, `"2"` → tier 2, `"3"` → tier 3, `"0"` → fully closed. Position-fraction goes 1.0 → 0.5 (after tier1) → 0.25 (after tier2: tier2 sells *half of remaining*) → 0.125 (after tier3: sells half of remaining) → 0.0 (full close).

| state | trigger (this bar) | action | remaining frac | fill price |
|---|---|---|---|---|
| flat (`tier == 0`) | `low < lower` | **BUY** full position (limit at `lower`) | 1.0 | `min(lower, open)` |
| in, no tier yet (`exit_id == "0"` or no closed trades) | `high ≥ middle` | **sell ½** (mark tier "1") | 0.5 | `max(middle, open)` |
| | `low ≤ entry_px × StopPercentage` (=0.9) | **close all** (mark "0"); then `if low > lower` → **re-enter** full at `lower` | → 0.0 (then 1.0) | `min(entry×0.9, open)`; re-entry `min(lower, open)` |
| tier-1 (`exit_id == "1"`, frac 0.5) | `high ≥ upper` | **sell ½ of remaining** (= ¼ of original; mark "2") | 0.25 | `max(upper, open)` |
| | `low ≤ entry_px` (break-even) | **close all** (mark "0") | → 0.0 | `min(entry, open)` |
| | `low ≤ lower` | **close all** (mark "0"); **re-enter** full at `lower` | → 0.0 (then 1.0) | `min(lower, open)` |
| tier-2 (`exit_id == "2"`, frac 0.25) | `low ≤ middle` (coming back down) | **sell ½ of remaining** (= ⅛ of original; mark "3") | 0.125 | `min(middle, open)` |
| | `low ≤ entry_px` | **close all** (mark "0") | → 0.0 | `min(entry, open)` |
| | `low ≤ lower` | **close all** (mark "0"); **re-enter** full at `lower` | → 0.0 (then 1.0) | `min(lower, open)` |
| tier-3 / runner (`exit_id == "3"`, frac 0.125) | `low ≤ entry_px` | **close all** (mark "0") | → 0.0 | `min(entry, open)` |
| | `low ≤ lower` | **close all** (mark "0"); **re-enter** full at `lower` | → 0.0 (then 1.0) | `min(lower, open)` |

Trigger-evaluation order within a bar (mirror the Pine's branch order): in each state, evaluate the *scale-out* trigger first, then break-even, then the lower-band close+re-entry. (E.g. a bar that satisfies both `high ≥ middle` and `low ≤ entry×0.9` in the no-tier state: the Pine evaluates the `high >= middle` branch then the `low <= entry*0.9` branch — so it sells ½ at the mean *and* closes the rest at the stop in the same bar. Replicate that.) The Pine's `strategy.exit(... profit=0.1, loss=0.1 ...)` is a hack to force the exit to fire immediately — treat each exit as a market/limit fill that bar, not a pending bracket order. Pre-tier-1 entry has a `tier == 0` gate (= flat) and `afterStartDate` (= within the backtest window — N/A for us, the window is the harness's start/end). Ignore `AccuracyTest` (a debug mode).

## THE APPROVED DESIGN — 4 pieces

**(1) Harness: `position_management` field on `StrategyMeta` + a `tiered_meanrev` walk path.** Add `position_management: str = "binary"` to `StrategyMeta` (and to `to_db_row()` so the `strategies` table records it — add a `position_management TEXT NOT NULL DEFAULT 'binary'` column to `schema.sql`, idempotent `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`). `run_backtest` checks `meta.position_management`: `"binary"` → the existing `_walk_signals` (unchanged — every current strategy keeps working bit-for-bit); `"tiered_meanrev"` → a new `_walk_tiered_meanrev(df, signals, *, starting_capital, cost_bps, stop_pct)` that consumes the strategy's `bb_lower`/`bb_middle`/`bb_upper` columns + `entry_long` (the "be dip-buying" signal — actual fill is the limit at `lower`) and runs the state machine above on a position carrying `remaining_fraction` and `entry_px`. Returns the same `(trades_df, equity_series)` shape so the rest of `run_backtest` (3-way benchmark, per-period stats, persistence, parquets) is unchanged. (Alternative considered + rejected: a stateful `manage(position, bar) -> actions` callback the strategy provides — breaks the "strategy = pure DataFrame transform" pattern; the mode approach keeps strategies declarative and leaves room for future `trailing_stop` / `pyramid_momentum` modes.)

**(2) Limit-at-level intrabar fills, owned by the mode.** Inside `_walk_tiered_meanrev`: a buy-limit at `L` fills at `min(L, open)` on any bar where `low ≤ L`; a sell-limit at `M` fills at `max(M, open)` on any bar where `high ≥ M`; a break-even close (sell at `entry_px`) fills at `min(entry_px, open)` on a bar where `low ≤ entry_px` (you wanted out, the bar traded down through your level — you get your level or the worse open if it gapped through); the lower-band close fills at `min(lower, open)` on a bar where `low ≤ lower`. All decisions use the *current* bar's bands (the Pine evaluates on the bar where the condition is met, fills intrabar). No slippage beyond the gap-through handling. `binary` mode stays next-bar-open — this fill change is scoped to `tiered_meanrev`.

**(3) The `vwema_bb` strategy.** New file `trading_tools/strategies/vwema_bb.py` (keep `vwema_bb_meanrev` as the binary baseline for comparison — do not delete or rename it). `@register(name="vwema_bb", description="VWEMA-BB Momentum — faithful Pine port: dip-buy at lower band, tiered ½/¼/⅛/⅛ scale-out, break-even exits, StopPercentage stop, lower-band re-entry.", direction="long", edge_status="contested", edge_source="RezzaHmt PipBoy V2 (TradingView Pine v5). User's anchor algo — faithful tiered port.", default_params={"period": 20, "alpha": 0.9, "std_mult": 2.0, "source": "hl2", "stop_pct": 0.9}, asset_classes=["equity"], timeframes=["daily"], position_management="tiered_meanrev")`. `signal(df, params)`: `bb = _base.vwema_bb(df, period=params["period"], alpha=params["alpha"], std_mult=params["std_mult"], source=params["source"])`; return `entry_long = (df["low"] < bb["lower"]).fillna(False).astype(bool)`, `exit_long = False` (the exits are the state machine, not a column), `entry_short`/`exit_short = False`, plus `bb_lower = bb["lower"]`, `bb_middle = bb["middle"]`, `bb_upper = bb["upper"]`. We port *only* the default-flag long path; `StrategyType 2-4`, `momentum`, `Short`, `squeeze`, `WithLTDMA`, `DoubleExponential`, `useEntryPeriod` stay out of scope (addable as params later — note them in the docstring).

**(4) Partial-fill cost model.** Each transaction (entry, each scale-out, full-close, re-entry) charged a *one-way* leg: `(cost_bps / 2) / 10_000 × |fraction_traded|` of the position's value at that point, deducted from cash/equity. A buy-full → scale-fully-out cycle ≈ `cost_bps` total (= a normal round-trip, consistent with `binary` mode which charges `cost_bps` once at exit on a 100%-in/100%-out trade). Record each transaction in the trade ledger (the `trades` parquet) — use rows with `side`, `entry_ts`/`entry_px` (the cycle's entry), `exit_ts`/`exit_px` (this transaction), `fraction`, `return` (net of this leg's cost), `cost_bps`, `pnl`, etc. — i.e. one trade-ledger row per *realised* scale-out/close so `n_trades`, `win_rate`, `profit_factor` and the per-period stats still compute (each partial close is a "trade" of size `fraction`).
