## WHAT WE'RE BUILDING (one paragraph, refined in the brainstorm)

A **registered cross-sectional quality strategy** (and possibly one or two variants) that ranks the universe by a *point-in-time*, *fundamentally-derived* quality metric and feeds that ranking into the existing V3.2 portfolio-overlay `rank_hold` mode (no new walk path needed). The strategy is a thin per-instrument `_walk_signals`-shaped fn that, on each bar, computes a `score` column = the chosen quality metric as of that bar (via `point_in_time_view` + `derived_metrics` on the symbol's `fundamental_facts`), and emits entry/exit signals that hold-while-ranked-top-K under the overlay (the per-instrument run is essentially "always-flat-without-the-overlay"; the value is in the cross-sectional ranking). The factor of choice is a **quality** factor (Novy-Marx 2013 gross profitability = gross_profit / total_assets; Asness, Frazzini & Pedersen "Quality Minus Junk" = a composite of profitability + growth + safety + payout) — NOT the growth-momentum the V3.3a study already falsified at this resolution. Cost-aware baseline through the V3.2 overlay: weekly rebalance, K∈{3,5,7} fitted on IS, equal-weighted (and maybe inv_vol), 60% per-position cap, GLD residual sleeve, 5 bps turnover cost, vs SPY-BH + universe_ew_bh + gold_bh, PSR(0.9) + DSR over the trial family.

## THE BRAINSTORM — what it needs to settle

Most of the architecture is fixed by V3.2 + V3.3a, so this is a shorter brainstorm than V3.3 was — but treat it as genuinely open. Decisions:

1. **The factor.** Strawman: **Novy-Marx gross profitability** (= gross_profit / total_assets, TTM) as the headline strategy — clean, single-metric, documented edge (Novy-Marx 2013, "The other side of value"), most of the inputs are already in `xbrl_map.METRIC_TAGS`. A second strategy could be **a quality composite** (a la QMJ: profitability + growth + safety, normalised) — adds complexity + a normalisation choice; consider keeping it as a follow-on. Decide: one strategy or two? Which metric(s)?
2. **The `score` definition exactly.** For Novy-Marx GP: `score = gross_profit_ttm / total_assets_latest` computed via `derived_metrics`'s existing helpers (or a tiny new helper; `derived_metrics` already produces `gross_margin = gross_profit/revenue` — need `gross_profit / total_assets`, slightly different). Confirm the formula + add a `gross_profitability` field to `derived_metrics` if not already there. Higher = better → `rank_hold` takes top-K by descending score.
3. **The `rank_hold` mode + the strategy interface.** Verify the V3.2 overlay's `rank_hold` mode reads `score` from the strategy's signal frame on every rebalance bar (it does, per the V3.2 spec — confirm) and that the strategy can emit `score` = NaN on bars where the fundamentals aren't yet available (the overlay must drop NaN-scored names from the rank at that rebalance). What does the per-instrument `_walk_signals` run look like when the strategy is meant to be cross-sectional-only? The `high_52w_breakout` precedent: emits `score` + ordinary `entry_long`/`exit_long` signals (it works standalone AND in the overlay). For a quality strategy, the standalone per-instrument run is less meaningful — maybe `entry_long = True` always (so the overlay sees a constant "in" signal and the rank decides selection)? Or emit a meaningful per-instrument signal (e.g. `entry_long = score > median(score across history)`)? Decide.
4. **Universe.** Stay on `TOP_25` (ex-SPY = 24 operating names, mirroring V3.2). Survivorship caveat carries forward. (V3.2b — a decorrelated/mechanical-point-in-time-screened universe — stays parked.)
5. **Fitted knobs.** `rank_hold` already fits K∈{3,5,7} on IS. Anything else? (E.g. a `min_score_threshold` floor — only hold names whose quality is above some absolute bar — adds a param.) Lean: no extra knob; K is the only fit.
6. **Weighting / cadence.** Default to `equal` + `weekly` (mirrors the V3.2 baseline). Add `inv_vol` weekly as a second run? `monthly` cadence as a third? Don't fan out the full grid; pick 1-2 runs.
7. **`gross_profitability` (or whatever the headline metric is) — point-in-time depth.** `fundamental_facts` starts ~2009 for most names; the strategy's score is NaN before each name has its first 4 quarters of TTM data. Decide whether the backtest starts only when ≥X names have valid scores, or accepts a thin early period.
8. **A registered `_walk_signals`-shaped strategy emits `entry_long`/`exit_long` per bar — and the per-instrument runs land in `backtest_runs`.** Decide whether `quality_gp` (or whatever) goes in `run_baseline.ACTIVE_STRATEGIES` (so future full re-runs include the per-instrument flat-ish version) or stays portfolio-overlay-only.

## STANDING RULES (don't re-litigate)

- **Point-in-time discipline is non-negotiable.** The strategy reads `fundamental_facts` via `point_in_time_view(facts, as_of=bar_date, lag_days=1)` — a fact filed on day `t` is first usable on the `t+1` bar. The look-ahead smoke test (V3.3a) is the guardrail at the data layer; the strategy must add its own assertion (a fundamental value as-of `bar_date` is never sourced from a `filed_date > bar_date - lag_days`).
- **Free data first** — SEC EDGAR is the source for fundamentals (already done); no new ingestion needed for this sub-piece.
- **Survivorship bias on `TOP_25` is acknowledged-and-flagged**, not pretended-solved; the result stated with the caveat.
- **Everything measured the same way:** cost-aware (5 bps turnover/rebalance in the overlay); full / IS (first 70% of bars) / OOS (last 30%) split; PSR(0.9) + DSR (multiple-testing-corrected); REAL EDGE in the overlay = OOS Sharpe > 0.9 ∧ DSR ≥ 0.95 ∧ beats *both* universe_ew_bh and gold_bh OOS; vs SPY-BH AND vs asset-BH (the per-instrument harness emits both); K (and any other tunable) fit only on IS.
- **`binary` stays the default `position_management`** — quality strategy is `binary`. The V3.2 overlay walk is the cross-sectional layer.
- **Schema is append-only + idempotent.** No new tables expected for this sub-piece (it's strategy + overlay; reuses existing `backtest_runs`/`portfolio_runs`).
- **Process:** brainstorming → spec → sign-off → writing-plans → plan approval → TDD implement with frequent commits → final verification + `git push` (branch `master`). One sub-piece at a time; don't open V3.3c until V3.3b-quality is shipped.
