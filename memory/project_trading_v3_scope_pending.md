- **V3.2 — Portfolio overlay. SHIPPED + pushed 2026-05-12** (commits e46375b…785c14f, GitHub Sc07713/trading-tools master; spec `docs/specs/2026-05-12-v3.2-portfolio-overlay.md`, plan `docs/plans/2026-05-12-v3.2-portfolio-overlay.md`). Equity-sleeve-only multi-instrument layer: a *portfolio run* takes one strategy, forward-fills its `entry_long`/`exit_long` into a per-name held-state (long-only — short cols ignored), and on a **weekly** cadence (∈ {daily,weekly,monthly}; rebalance bar = first available trading bar of each ISO week/month) holds ≤7 cash-equity positions + a **gold (GLD) residual sleeve** ("when in doubt hold gold" → zero theses = 100% GLD; one lone thesis = 60% it / 40% GLD). Two trim-to-7 modes: **basket** (greedy highest-avg-pairwise-|corr| drop, 120d window) and **rank_hold** (top-K≤7 by a strategy-emitted `score` — only `high_52w_breakout` has one: `close / rolling-252d-high`). Held names weighted **equal** (default) / **inv_vol** (60d) / **risk_parity** (120d cov, damped multiplicative ERC solver, inv-vol fallback), then a hard **60% per-position cap** (excess pro-rata, then to gold). Cost = one-way turnover × `cost_bps`/10000 per rebalance (default 5 bps). **Marking convention: buy-at-close / mark-at-close throughout** (deliberate simplification vs `_walk_signals`' next-bar-open — makes "100% gold ≡ gold-BH" an exact test). **Fit-only-K-on-IS:** rank_hold's K∈{3,5,7} is the *only* fitted param (grid-searched on first 70% of bars by cost-adj IS Sharpe, frozen, OOS on frozen K); 3-pt grid feeds DSR `n_trials`; basket has no fitted param ⇒ IS/OOS is a stability check there. **Four-way benchmark** (all mandatory): strategy / spy_bh / `universe_ew_bh` (1/N of each universe member, drift, one round-trip cost on last bar) / `gold_bh`. **Verdict** (strategy/OOS row): REAL EDGE = OOS Sharpe>0.9 ∧ DSR≥0.95 ∧ beats *both* universe_ew_bh & gold_bh OOS Sharpe; PROMISING = OOS Sharpe>0.9 ∧ PSR(0.9)≥0.95; else NO EDGE. - **VWEMA-BB tiered-exit port (DESIGNED 2026-05-12, plan/impl pending — NEXT SESSION's primary task).** Faithful port of RezzaHmt's VWEMA-BB Momentum Pine strategy's long/default-flags path (`Short=0`, `momentum=0`, `StrategyType=1`, `useEntryPeriod=0`, `WithLTDMA=0`) — the V2 port `vwema_bb_meanrev` lobotomised it to binary in/out; this restores the real logic: buy a full position at the lower band (limit) when `low < lower` → sell ½ at the middle (VWEMA) when `high ≥ middle` (tier1) → sell ¼-of-original at the upper band when `high ≥ upper` (tier2) → sell ⅛ at the middle on the way down when `low ≤ middle` (tier3) → ⅛ runner that closes at break-even (`low ≤ entry`) or at the lower band (`low ≤ lower`); break-even exits at tiers 1/2/3 too; a `×StopPercentage` (0.9) stop on the *pre-tier-1* state; whenever a trade closes at the lower band, immediately re-enter a fresh full position there. **Design (approved):** add `position_management` to `StrategyMeta` (default `"binary"` = today; new `"tiered_meanrev"` mode) — the harness gets a second walk path that consumes the strategy's `bb_lower`/`bb_middle`/`bb_upper` columns + runs the state machine, and the mode owns **limit-at-level intrabar fills** (buy-limit at `L` fills `min(L,open)` when `low≤L`; sell-limit at `M` fills `max(M,open)` when `high≥M`) — which also fixes the "next-bar-open bias" harness-debt item, but only inside this mode. New strategy file `strategies/vwema_bb.py` (keep `vwema_bb_meanrev` as the binary baseline for comparison), `default_params={"period":20,"alpha":0.9,"std_mult":2.0,"source":"hl2","stop_pct":0.9}`, uses the existing `_base.vwema_bb` primitive. Partial-fill cost model: each transaction (entry / each scale-out / full-close / re-entry) charged `(cost_bps/2)/10000 × |fraction_traded|` of position value. Single-instrument only — the V3.2 portfolio overlay can't represent fractional positions.
